# 产品一页纸｜日刻 DayTally

## 定位

**桌面优先的每日自我量化工具。**
把“今天做了多少”放在手机桌面，用一次点击替代一次完整的记录流程。

- 品类：习惯追踪 / 自我量化 / 轻健身记录
- 形态：Android App + 桌面小组件 + 可选局域网同步
- 当前阶段：可安装、可日常使用的独立产品（1.2.12）
- 开发方式：个人独立开发，Kotlin 原生 View + Canvas，无第三方 UI 框架

---

## 问题

记录本身，比运动还难坚持。

现有很多健身/习惯 App 的记录路径是：

> 解锁 → 找 App → 打开 → 选项目 → 选日期 → 填数值 → 保存 → 返回

一次记录 10～30 秒，还要穿越通知、课程、社区、广告。

结果：

- 用户不是不想记，是 **记一次太麻烦**。
- 一旦断档，负罪感让用户彻底放弃。
- App 越“丰富”，越容易把核心动作埋起来。

---

## 洞察

**坚持不是靠提醒，是靠把动作缩短到不需要决定。**

当记录动作只有一次点击，且发生在用户已经在的地方（桌面），它才可能变成无意识习惯。

日刻不是“更漂亮的记录 App”，而是 **把记录从 App 里拿出来，放回桌面**。

---

## 解决方式

### 1. 桌面就是主界面

- 4 个 1×1 方块：俯卧撑 / 蹲马步 / 引体向上 / 自定义
- 2 张 4×2 大卡：身高、计数（7 天矩阵 + 项目切换）
- 点方块 = 加一组；长按 0.15 秒 = 减一组
- 单击 36ms 最大振幅触感，口袋里也能感觉到

### 2. App 只做“看”和“改”

- **今天**：今天累计 + 本周 7 天条带
- **趋势**：30 天折线、最高 / 7 天变化 / 最低、逐日明细
- **项目**：每组数量、累计、目标、纵轴范围
- **隐藏设置**：桌面长按接管、同步服务

### 3. 两台手机实时同数（1.2.12）

- 一台桌面点一下，另一台不打开 App，桌面组件约 1 秒跟着变
- SSE 长连接，不轮询；服务端写入后才推 `change`
- 事件合并：A 加 3、B 加 1，最终是 4，不是覆盖
- 只走局域网；服务端可以是一台树莓派

### 4. 数据是自己的

- 默认只存手机本地
- 不登录、不上传公网
- 公开包不含任何服务器地址或 Token
- 要同步，用户自己填 IP、端口、访问令牌

---

## 差异点

| 常见产品 | 日刻 |
|---|---|
| 打开 App 才能记录 | 桌面点一下就能记录 |
| 记录是“任务” | 记录是“顺手一下” |
| 社区/课程/勋章驱动 | 数字本身驱动 |
| 云端账户 | 本地优先，可选局域网 |
| 通用习惯追踪 | 深挖“组数 / 次数 / 身高”三种记录 |

---

## 谁会觉得它有用

- 在家做俯卧撑、蹲马步、引体向上的人
- 想记录孩子身高、自己身高变化的人
- 讨厌健身 App 太吵、太游戏化的人
- 有两台手机 / 平板，想让数据自然同步的人
- 在意数据隐私、愿意自己搭一个小服务的人

---

## 商业可能性（假设，不是承诺）

> 这一节是给投资人/导演理解“可以往哪拍”，不是当前已实现功能。

1. **免费核心 + Pro 增值**：更多主题、更多组件尺寸、跨设备同步托管、数据导出。
2. **家庭场景**：孩子身高、父母健康记录，多设备同步是天然需求。
3. **B 端轻量工具**：健身教练给学员的“只记组数”工具，去掉社交和课程。
4. **硬件联动**：与体重秤、身高尺、家庭 NAS 做本地数据接入。

当前现实：**1.2.12 是可用产品，不是商业闭环。** 没有付费、没有增长数据、没有团队。视频不要把它包装成已规模化公司。

---

## 投资/媒体一句话

> 日刻把每日记录从“打开 App 填表”变成“桌面点一下”。它不试图用内容留住用户，而是让记录动作小到不会被打断。

---

## 产品边界（诚实写清）

- 仅 Android；没有 iOS。
- 长按减组需要 Vector / LSPosed 模块；不装也能单击加组。
- 双机同步是局域网长连接，不是系统级推送；MIUI 需要允许自启动、省电无限制。
- 多任务界面里点方块可能误加组，这是已知取舍。
- 数据默认本地，没有云备份；换机需要自己迁移。
